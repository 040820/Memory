# 证据驱动记忆：基线与受控案例实施计划

**目标：** 先验证原始 LiCoMemory 和评测接口，再检验写入更新与证据约束是否改善个人长期对话回答。

**架构：** 原始数据只读；分别构造可见输入、不可见评测标签和结果。受控样例用于机制诊断，公开数据用于问答与检索评测；任何结论均附数据、模型、时间协议及失败数。

**环境：** Windows、Python、Conda `licomemory`；当前项目无 Git 元数据，原项目与已有文件不覆盖，实验内容放本目录。

**状态：** 冻结样本和 10 个受控样例已生成，未运行 LiCoMemory、未计算模型性能。模型服务、模型名称、可用密钥和完整依赖仍待确认。

## 数据、任务与冻结

`frozen_sample.json` 保存三个原始文件 SHA-256 和开发诊断样本 ID，随机种子 20261101。仅用于接入调试：LoCoMo 2 段对话，LongMemEval 的 knowledge-update、temporal-reasoning、multi-session 各 2 题，MemConflict 2 个独立人物。各项计数单位不同；开发样本不应被当作独立测试集或代表性样本。现有人工试标样本可能与开发样本重叠，后续正式研究须按人物/对话/事件链隔离并记录重叠。正式基准先冻结全量或明确选样规则；不要只挑对我们方法有利的例子。

LongMemEval 单题使用该题完整 haystack；LoCoMo 使用目标对话的协议允许会话；MemConflict 人物隔离、会话顺序输入，逐问题查询时只能看到该时点已提供的历史，具体触发时机在适配官方协议后冻结。标准答案、gold evidence、has_answer、MemConflict 档案/After/Before/outline、冲突标签均不得进入构建、检索、Judge、Reader；评估时单独访问。注意现有 LoCoMo 转换 `D10:3` 到 `D1` 错误；要保留原始证据 ID。不可用它的错误转换结果充当依据准确率。

时间协议需分别报告：(A) 基准兼容，明确各数据集原始上下文和排序，不擅自变更；(B) 严格在线，记录本题可见截止点，只使用此前可见证据，保留原始时间、精度、同时间顺序策略和异常。LongMemEval 部分同日会话晚于问题时间，时间冲突需单列，不能静默改写标签或混同两种分数。LoCoMo 没有普适逐问题提问时间时，不虚构时间点。

## 受控测试

`controlled_inputs.json` 为系统可见对话和问题，`controlled_gold.json` 为只给独立评测器使用的期望；`validate_cases.py` 检查 ID 匹配、基本输入隔离和原文引用。10 案例覆盖变化、纠正、计划、人物归属、并存、冲突、否定、未来工作、属性范围和模糊时间。它们是人为设计的诊断，不是人类标注的真实对话，答案与动作是待人工复核的评测规范，允许多个合理动作，不能用于声称普遍准确率。
