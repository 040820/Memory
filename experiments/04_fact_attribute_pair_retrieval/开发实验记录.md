# 实验 04：事实级配对开发实验记录

## 执行范围

使用实验 03 的同一道已查看过的 LongMemEval 开发题的 `source_inventory.json`：覆盖 44 个会话中有用户内容的 43 个会话、221 条用户发言；不包含助手相邻轮次，不能声称覆盖完整对话上下文。事实抽取和配对只接收来源清单，不接收问题、标准答案或答案会话标注。会话原始 ID 仅用于分组、时间和证据定位；模型请求不发送该 ID 字符串。题目已用于开发，不是独立盲测。

事实抽取使用用户指定的线上 `qwen3.8-flash`，关闭思考输出；每个会话单独原始响应和 checkpoint、并发数 4，无整体时间上限。有效状态没有更新。程序只核对引用存在，不证明主体、属性、值或归一语义成立。

## 事实提取及恢复

`runs/01_fact_pairing_a2f3aa27_20261101/` 首轮 43 个会话中 41 次解析成功、1 次截断、1 次响应为顶层对象列表而未解析。首轮 233 个未验证事实候选、4 项跳过；其 16 组候选对没有覆盖目标数值对。原始记录不覆盖，服务返回总 token 87399。

检查首轮结果后，发现两条目标事实分别被模型标为 `social_media_followers_count` 和 `follower_count_estimate`，对象均为 instagram，直接使用原始键不能配对。新增 `src/normalization.py` 中的 `lexical_v1_dev` 候选键规则，把有明确平台的 `social_media` 前缀、`followers` 与 `follower` 词形、末尾 `estimate` 作有限的可追溯规范化；保留原始键、规则及版本，近似性保留在原始值和模态里。规则是在查看这道开发题后补充的，不是盲测设计，不能用该题证明泛化。

`runs/02_fact_pairing_recovered_normalized_20261101/` 复用 41 个成功会话；对 1 个格式错误会话的原始响应事后重新解析，没有重新请求模型；对截断会话拆为 6 个用户轮次独立补跑，均完成。此恢复有 48 个成功处理单元（41 会话 + 1 事后重解析会话 + 6 轮次，不是 48 个原会话），267 个候选事实、4 个跳过、17 个候选事实对；4 个跳过及其原因保留在输出。补跑响应服务报告 7724 token。模型输出、提取粒度和恢复方式不同，这些候选数不代表准确率。

## 目标开发配对

在事后检查中，新的 17 组候选中包含：旧 1250、原属性 `social_media_followers_count`、Instagram；新 `close to 1300`、原属性 `follower_count_estimate`、Instagram、`POSSIBLE`。两个派生键都是 `follower_count`，配对路径为 `proposed_normalized_attribute_key`；旧范围 UNKNOWN、新范围 current，范围匹配标为 UNKNOWN。原始值、证据 ID、原文 span 和原始属性键均保留。匹配只生成 candidate，不证明属性归一或事实关系正确。

`runs/03_pair_relation_shadow_20261101/` 对全部 17 对调用关系模型，17 条产生 proposed 关系，其中 1 UNRELATED、11 DUPLICATE、3 COMPLEMENT、1 COEXIST、1 CHANGE，模型语义尚未经独立标签评估，不能把这些计为准确结果。开发目标对被模型标记 CHANGE，并解释为已增长：原文只有“我认为接近 1300”，该解释可能过于确定。全部 action=DEFER 且 applied=false。服务报告总 token 18203。

随后代码增加 `NEW_STATEMENT_UNCERTAIN` 等 caveat，不改变既有响应。`runs/04_pair_shadow_caveats_posthoc_20261101/` 是对已冻结响应的**事后代码重解析**，不是新模型运行：目标对同时标记 MODEL_RELATION_UNVERIFIED 和 NEW_STATEMENT_UNCERTAIN，eligible_for_state_update=false。不能据此说模型自己改变了判断。

## 回答预检及局限

`runs/05_answer_fact_pair_probe_20261101/` 在回答阶段复用 03 相同 12 条检索来源；仅选择双侧 evidence ID 均在该上下文中的候选建议，不用 gold，得到 1 对提示。读取到 03 的问题后调用同一个线上 Reader，服务报告总 token 2323，引用 ID 存在但未验证语义。输出仍说先前 1250、后来认为接近 1300，并表示准确当前数值未知；03 只给原文的基线也给出近似意思。此结果不能证明回答提升，且额外候选提取、关系判断和提示会增加成本。

对用户真实问题的结果仍需独立按原始问题与答案评分；此前开发题标准答案是 1300，但原文为近似陈述，不能简单把“1250”和“1300”是否出现等同于严格对错。实验 04 实际还发现有同属性的多次重复说法与无关候选，因此不能将键匹配当成确认的同一事实。固定 K=10 截断、UNKNOWN 范围、未提取/错误提取、未实现多路属性别名及未知项恢复都会影响召回；本次 0 次截断只是该样本结果。开发题调过别名后不能再用它评估泛化。后续需要冻结未经调试的多题样本，建立独立人工标注，并报告事实抽取覆盖、端到端配对 Recall@K、误配率、回答准确性、证据支持和成本；尚未接入 LiCoMemory 主图或任何真实状态提交。
