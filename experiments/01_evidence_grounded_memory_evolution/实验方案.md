# 实验 01：证据驱动的记忆演化与回答

**状态：设计中，尚未实现或完成实验**  
**实验目录：** `01_evidence_grounded_memory_evolution`  
**研究范围：** 个人长期对话中明确陈述的生活事实及其变化。

## 1. 实验目的

在原始 LiCoMemory 上设计并验证：新旧对话能否被正确关联，系统能否依据原文区分事实变化、纠正、并存与证据不足；这种处理能否改善当前、历史及变化类回答，并保留可追溯依据。

## 2. 实验内容

1. 建立证据、事实候选、状态版本及更新决策的基本记录；支持保存原文位置、说话人、时间、模态与不确定性。
2. 检索可能受影响的旧事实，判断新旧关系；证据充分时提出更新，证据不足时保留冲突或暂缓。
3. 回答时按问题时间使用适用状态、历史及原始证据，检查回答是否过度确定或混用旧状态。
4. 设置 `off` 原始基线、`shadow` 只记录建议、`active` 通过门控后提交三个模式；先验证基础链路，再比较效果。

## 3. 数据与模型

- 受控案例：使用现有 `experiments/evidence_memory_pilot/controlled_inputs.json`，独立的 `controlled_gold.json` 仅用于评测；案例需人工复核，属于机制诊断。
- 公开数据：LongMemEval、LoCoMo、MemConflict；先使用已冻结的开发样本检查链路，再明确正式样本与时间协议。
- 模型：当前计划使用服务器 `qwen3-8b`（关闭思考模式）和 `bge-m3`；记录实际模型配置、版本、请求参数及向量维度。

## 4. 对照与指标

- 对照：原始 LiCoMemory；简单时间优先；回答时比较新旧证据；本实验方法。需尽可能保持模型、输入与检索预算一致。
- 更新：受影响旧事实召回、关系判断、误更新和漏更新；无人工标签时明确说明指标不可计算。
- 回答：当前与历史问题的答案、证据召回/支持、旧状态误用、模型调用与耗时；模型裁判结果单列为代理指标。
- 重点区分“标准答案是否匹配”和“原文是否支持精确结论”；不将近似或不确定陈述改写为确定事实。

## 5. 流程与验收

1. 冻结数据、配置和可复现的开发样本，检查原始输入与评测标签隔离。
2. 实现证据与事实记录，先运行 `shadow`；检查原文引用、主体、时间、模态及状态候选。
3. 加入门控、状态版本和回答路径；先在受控案例上核验，再进行公开数据比较。
4. 保存配置、输入指纹、代码版本/哈希、执行日志、检查点、原始结果、失败情况和分析报告；每次重复运行使用独立目录。

**验收：** 能追溯每次建议与实际提交的依据；相关受控案例可检查；比较结果报告每组分子、分母、失败数及局限。单题预检、接口通畅或模型代理评分不能视为研究效果已验证。

## 6. 当前进度

此前一次 LongMemEval 单题开发预检已完成恢复查询，但不构成整体基线；现有实验材料位于 `../evidence_memory_pilot/`，不移动、不覆盖。本方案不代表新模块已经实现。
