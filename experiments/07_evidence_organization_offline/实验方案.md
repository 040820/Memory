## 目标与边界

在保留原版实体 DiGraph 与原版运行方式的前提下，完成目标结构：

`LiCoMemory 原有实体图 + 独立事实记录 + 事实变化记录 + 原始 Chunk`

本次只解决**记忆组织与证据可找回**：Chunk 来源与防覆盖、关系去重前的事实捕获、从实体出发的独立事实召回、候选变化记录、持久化与开关兼容。不含模型关系审查、可信状态更新、依据链参与回答；不宣称回答效果提升。候选 change 不自动生效、不覆盖旧记忆。

## 设计选择

1. **Chunk ID** = hash(session_id, 顺序)：跨 Session 同原 ID 不覆盖；同 Session 完整重放幂等，新序号追加接受，同序号内容变化拒绝；`source_chunk_id` 保留原始数据集 ID。
2. **事实 ID** = hash(src, relation, tgt, evidence_id)：同实体不同关系、同关系不同来源均独立保留；`raw` 原始谓词与实体原样保存，canonical 仅作索引别名。
3. **捕获时机**：实体映射之后、关系去重之前；去重只影响图侧，证据库不受影响。
4. **变化记录**：仅允许 candidate + 有来源 + 有原因；`decision` 不入哈希，旧 pickle 无该字段按 `pending` 加载。
5. **complete 语义**：开关开且新构建 = 完整；开关关 / 无 evidence 键的旧 pickle / 旧格式 pickle = 不完整，不虚构恢复结果。
6. **开关关闭** = 原版行为不变（含原版 add 模式跨 Session chunk ID 冲突的既有缺陷，本次不在关闭路径修复）。

## 与原版差异

- 默认开关关闭时与原版一致；开启后 chunk 获得 Session 命名空间 ID（原全局序号保留为 `source_chunk_id`）。
- 查询结果中的 `evidence_fact_candidates` / `evidence_candidate_traces` 语义未改（5ad25fe 已有），仍为诊断输出、不进回答 prompt。
- 其余构建/检索/评估路径未改动。

## 已知限制

- `decision` 不入 change 哈希：同 (old, new, relation, evidence, reason) 不同 decision 会覆盖；审查功能落地时需升版本（version 1 → 2）。
- 同 (src, relation, tgt, evidence) 重复抽取以最后一次 `raw` 为准（同 ID 幂等覆盖）。
- 事实检索为实体精确（casefold）匹配加别名，无语义召回。
- 未在真实模型抽取下验证端到端；未跑 LongMemEval / LoCoMo 基准。
- `_dynamic_add_chunks` 为弃用路径，本次仅补命名空间防护，主路径为 `add_single_session`。
