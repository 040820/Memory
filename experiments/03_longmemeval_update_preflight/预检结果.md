## 后验检查

`offline_evaluation.json` 在所有模型输出完成后单独写入答案、答案会话和对照，不进入任何模型。基准答案为 1300；原文较早说 1250，稍后说“我认为现在接近 1300”。两条相关答案会话均在本次展示来源中（2/2）；但入选的 8 组关系候选中，没有把这两条数值陈述直接配成一组。两种回答都同时提到先前 1250 和随后接近 1300，并说明更晚问题日期的确切值无法确定。由于标准答案只有 1300 而原文有“接近/认为”，不在此直接给两种回复判对错；独立评分及原文支持须另行定义。

两模式检索原文相同：12 条来源；基线 prompt 1784 / total 1993 tokens，关系提示模式 prompt 5280 / total 5483 tokens；另有 8 次关系判断共 7379 tokens（本地 embedding 成本未用远端 LLM token 计量）。关系模式增加了上下文与额外调用，不是严格相同 token 预算。两模式引用 ID 均存在，但语义支持未独立验证；没有修改记忆。该对照使用简化 BGE 检索与线上 Reader，不是 LiCoMemory 原始系统基线，也不是 active 演化方法。

## 发现与下一步

最直接的瓶颈是**相关信息可以在回答原文中被召回，但关系候选未配到需要比较的两条数值事实**；近邻只按完整发言语义选 1 条旧发言，受同主题但非同属性内容干扰。说明“问题答案证据召回”和“新旧事实对召回”是不同目标。后续应让候选事实先显式提取主体/属性/值，再结合会话和上下文为同属性的多个旧事实召回排序；使用事后人工核查的开发对评估召回，不把 gold 会话作为输入或直接指定候选。

此题仅一例，不估算关系准确率或回答增益；比较公式和判分标准须先冻结，再做多题盲测。当前状态库没有接入、未真正更新记忆，指代/语义审查与真实检索的效果和开销需要完整实验验证。预检模块测试 11 次执行通过，其中含继承重复，只验证覆盖的程序路径。

**上下文限制：** 本轮遍历了 44 个会话中全部 221 条用户发言，但候选构建与回答上下文没有输入助手发言，也没有按原会话组织完整相邻上下文；因此是“覆盖全部用户发言的轻量预检”，不是完整对话上下文的正式端到端实验。对需要助手发言、跨轮指代或会话上下文的问题可能发生遗漏或误解。
