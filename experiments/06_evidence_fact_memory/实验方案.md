# 06 事实与证据记忆组织
状态：开发中。保留 DiGraph；独立记录原始 Chunk、抽取关系及其来源、事实间候选关系，实体索引召回；旧索引无法恢复历史丢失事实，必须标记不完整。保留基线开关，候选不可自动更新状态或作为已验证事实进入回答。
验证：多会话 Chunk ID、同实体不同关系、跨来源同事实、保存重载、双向追溯和配置关闭行为；不调用模型、不使用基准答案。与服务器已有编号恢复连接后核对。

## 本地实现与使用

在项目内新增 `coregraph/evidence_memory.py`。`graph.enable_evidence_memory: true` 启用新版捕获；默认 false 保持旧版。启用后整批建图和单 Session 增量处理以 Session + 顺序生成稳定 Chunk ID；同一 Session 每次必须提供顺序一致的完整 Chunk 序列，重复 ID 内容变化会拒绝覆盖。抽取结果在关系去重前按来源独立记录，保留原始谓词与实体及规范实体别名；结果只能称为未验证抽取候选。实体检索将独立事实返回为 `evidence_fact_candidates`，不自动进入回答上下文。变化记录仅允许 candidate，`evidence_bundle` 可双向取回两端和原文，不代表模型判断或已提交更新。

图与独立记录一起存储；旧索引标记 complete=false，无法恢复已丢关系，建议从原文重建。关闭开关生成的索引同样标记不完整。旧图仍是 DiGraph，独立事实索引并未替换默认三元组排序。

## 状态与限制

基础结构与捕获/保存/候选检索路径已接入；尚未实现模型关系审查、自动生成变化链、证据支持验证、可信状态更新、查询时把审查通过的链送入回答。不是完整冲突处理或问答方法；无法证明回答提升。需要进一步实测含真实提取的端到端行为以及多个相同 Session 重放或追加策略，不得直接覆盖。服务器已有版本与实验序号待同步核对。

## 本地验证

纯存储 5 项、真实模块接口和旧索引 2 项单元测试；py_compile。未调用在线模型、未运行数据集基准。

## 开启方式

在实际使用的配置文件 `graph:` 下设置 `enable_evidence_memory: true`。建议对完整原始语料新建索引；旧索引中已合并的事实无法重建。读取结果的 `evidence_fact_candidates` 与 `evidence_candidate_traces` 是调试输出，不在默认 Reader 的回答上下文中。
