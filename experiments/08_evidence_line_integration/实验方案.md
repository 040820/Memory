# 08 证据判断链与记忆组织链的连接

状态：实施中（2026-11-04）。本地新增编号；服务器 01–04 与本地 05–07 已在 `../INDEX.md` 登记，合并时防止编号冲突，不覆盖既有记录。

## 目标与边界

把两条已完成的线接起来（仍只做**记忆组织与证据可找回**，不越界）：

- **判断链（服务器 01–04）**：抽取 → 语义审查 → 新旧配对 → 关系判断，全程影子（`applied=false`）。
- **组织链（本地 05–07）**：Chunk 命名空间 → 独立事实 → 变更事件 → 召回，离线验证。

连接 = 把判断链的三种输出写入组织链的对应位置，**全程 shadow、候选永远是候选、gold 不进模型、不提交任何状态**。服务器 `StateStore`（active 提交门控）明确不接，属 11-01 计划 P1。

## 三个桥

| 桥 | 判断链输出 | 组织链落点 |
|---|---|---|
| 1 抽取写入 | `fact_extraction_v2` 五维限定词候选（逐字引文核对） | `EvidenceMemory.add_chunk`（命名空间）+ `add_fact`（raw 保留全字段） |
| 2a 单候选审查 | `semantic_review_v22` 路由 DEFER/REVIEW_NEXT/TECHNICAL_ERROR + 组件锚点 | 新增 `record_review`：事实 `support_status` + 审查历史（fact 身份不变） |
| 2b 配对变更 | `pair_retrieval` 候选对 + `relation_judge` 关系提议 | `add_change`（relation=模型关系，decision=pending，review_id 幂等） |
| 3 召回透出 | 审查状态与历史 | `evidence_fact_candidates` / `evidence_bundle` 自动携带 `support_status` 与 `reviews` |

## 关键设计

1. **ID 权威**：本地 fact_id = `hash(src, relation, tgt, evidence_id)` 为权威；服务器 evidence_id（dataset/conversation/session/turn 哈希）存于 chunk 的 `server_evidence_id` 与 fact raw 的 `evidence_id`，双轨可溯源，不互相替换。
2. **粒度映射**：服务器 evidence = 一个轮次；bridge 将每个轮次直接建成一个 chunk（`chunk_id=turn_id`，命名空间后为 `session_chunk_`），文本一致可核对。
3. **配对视图**：从本地事实派生 `subject_key/attribute_key/object_key/scope_key`（`normalization.lexical_v1_dev`，candidate_only），`session_time` 取 chunk 的 `raw_session_time`，`turn_index` 取 `source_chunk_id`；缺任一项进 `unindexed`，不猜测。
4. **LLM 传输注入**：bridge 接收 `async callable(payload)->str`，离线测试用 Fake 响应；真实调用（线上 qwen3.8-flash）后续接入，凭据不入库。
5. **vendor 规则**：只复制纯函数模块到 `coregraph/evidence_review/`（逐字节一致，来源头注明），`store.py`（fcntl）不复制。
6. **两个实现期发现的键映射**（已入测试）：① `add_chunk` 的存储键是 `hash(sid, 命名空间 chunk_id)`，与 payload 内 `chunk_id` 字段不同，事实必须引用存储键；② 抽取词表 `subject/predicate/value` → 存储词表 `src/relation/tgt` 在桥内映射，原字段保留在 `raw`。

- **桥 1（3 项）**：双 session 4 轮次 → 4 命名空间 chunk + 2 用户事实（assistant 轮次不抽取、限定词在 raw、`server_evidence_id` 双轨、重放幂等）；服务器 evidence_id 稳定唯一、缺身份字段报错；非 user 主体与引文不匹配的候选被跳过且留分母。

- **兼容（2 项）**：version 3 负载可加载、往返升 version 4；vendor 模块无 `fcntl`。

## 已知限制

- 抽取/审查/关系均为影子提议：引用定位 PASS ≠ 语义支持；关系模型与抽取模型同源时非独立验证。
- 配对依赖 `raw_session_time` 可解析（`%Y/%m/%d (%a) %H:%M`）与 `source_chunk_id` 为整数，否则该事实 `unindexed` 不参与配对。
- 单轮抽取不解决跨轮指代（与 01 相同限制）。
- 真模型端到端（线上凭据）未运行；本实验测试全部离线 Fake 响应。
