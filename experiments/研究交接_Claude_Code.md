## 1. 研究目标

研究长期个人对话 Agent 的记忆冲突与可解释回答，初期重点是用户明确陈述的生活事实。目标：当新旧陈述可能冲突时，找到原始对话依据，区分状态变化、明确纠正、补充、共存和证据不足，决定更新、保留或暂缓；后续回答能使用与问题相关的有效事实，并可追溯处理决定和原话。时间是辅助属性，不是单独研究中心。目标投稿 CCF-B；创新性和性能需通过文献对照与实验验证，不可预先宣称。

示例：旧句“住上海”，新句“已经搬到北京”可支持变化；“打算搬到北京”只是计划，不能视为已搬家。旧句“1250 粉丝”，新句“现在接近 1300”，问约多少可回答“约 1300”；不应将其擅自写成精确 1300 或证明具体增长原因。基准答案与原文是否足以证明纠正/替代是两回事。

## 3. 计划的记忆组织

保留 LiCoMemory 实体 DiGraph 作为关联入口，增加独立事实记录、事实变化/处理记录与原始 Chunk：

`Session -> 多个 Chunk -> 原始事实候选(独立 ID、原始实体/关系/值及来源) -> 事实间关系和决定(旧/新 ID、证据、原因、状态)`。

同一实体间不同关系必须独立保留；相同属性变化可能关联不同对象（用户-居住-上海 / 用户-居住-北京）。实体相同或相似不意味着事实冲突。独立事实索引必须能从命中的实体召回相关事实，不能依赖 DiGraph 被合并的边。`MultiDiGraph` 不是必需；若无法保证召回与证据，基于代码分析重新评估。

写入：保留来源 -> 抽取候选 -> 查找可比较旧事实 -> 结合原文审查 -> 记录关系/决定及依据 -> 证据充分才提交状态，否则暂缓。读取：检索问题相关事实 -> 由任一端查找相关变化记录及原文 -> 依据问题选择 -> 简洁回答并支持追溯。找到候选、来源存在、原文支持、更新证据充分是不同结论；不可把候选或同模型自审视为事实证明。历史状态不可简单删除。
